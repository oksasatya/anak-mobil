# AM-14 — Mobile project bootstrap and build pipeline

> **For agentic workers:** REQUIRED SUB-SKILL: use `executing-plans-hybrid` to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** scaffold `apps/mobile` (React Native + Expo, Expo Router, custom dev client) into the Bun workspace so it installs, type/lint-gates, runs on a real phone against the right per-profile API URL, and has its own CI job — and stop there.

**Architecture:** an Expo SDK 57 app joins the existing `apps/*` Bun workspace. `app.config.ts` reads an `APP_VARIANT` env var to pick the app id, display name, and which `.env.<variant>` file supplies the one public value the bundle carries (`EXPO_PUBLIC_API_URL`). A single healthcheck screen (`app/index.tsx`) renders the active profile and resolved URL and calls `/healthz`, doubling as AC1's "it opens" proof and AC3's per-profile proof. A `make mb-check` target (typed-routes generation → `tsc --noEmit` → `expo lint`) is the JS/TS gate, mirrored by a path-filtered `mobile.yml`. The native build and the on-device proofs are the owner's, run once locally with no cloud dependency.

**Tech Stack:** React Native · **Expo SDK 57.0.0** (`--template default@sdk-57`) · Expo Router (typed routes) · custom dev client · Bun (workspace + `--frozen-lockfile`) · TypeScript strict · EAS (configured, not required for AC1).

**Spec:** [`docs/superpowers/specs/2026-08-19-am-14-mobile-bootstrap-design.md`](../specs/2026-08-19-am-14-mobile-bootstrap-design.md) — read it alongside this plan. Every `[revised]` (cross-model pass) and `[grill]` (repo-docs grill) tag in the spec is binding; this plan implements those decisions and does not re-open them.

## Global constraints

Copied from the spec and from the repository's own `CLAUDE.md` / `apps/api`. Every task's requirements implicitly include this section.

- **Expo SDK is pinned to `57.0.0`, never floated.** Scaffold with `--template default@sdk-57`; the resolved `expo` version in `apps/mobile/package.json` is `~57.0.0` (a caret/tilde on a pinned major, as the template writes it), never `create-expo-app@latest` with a floating template. A floating scaffold is not reproducible — two clones a month apart get different code. (Resolved at plan time: stable is **57.0.0**; Expo Go targets `sdkVersion 57.0.0`.)
- **Bun is the package manager**, `bun install --frozen-lockfile` is the `npm ci` equivalent and MUST leave the root `bun.lock` unchanged. No nested `package-lock.json` / `yarn.lock` inside `apps/mobile` — a nested lockfile resolves a different tree than the one CI enforces. The one pre-authorized exception is the Bun contingency in Task 8.
- **Node LTS is a required local peer even on Bun.** `expo prebuild` shells to `npm pack` internally to stage native template packages; that path assumes a `node`/`npm` on `PATH`. Documented as a prerequisite, not discovered when prebuild fails.
- **The dev/`.env.development` API URL is the dev machine's LAN IP** — `http://<lan-ip>:8080`, **never `localhost`/`127.0.0.1`**. A physical phone's loopback is the phone, not the host. The API already binds `0.0.0.0:8080` (`.env.example:28 BIND_ADDR=0.0.0.0:8080`), so the LAN IP is reachable. A simulator, which shares the host loopback, may use `localhost`; a physical device may not.
- **`EXPO_PUBLIC_API_URL` is the only value the bundle carries, and the only variable that ever gets an `EXPO_PUBLIC_` prefix.** Babel inlines `process.env.EXPO_PUBLIC_*` and nothing else; a secret would never be given that prefix, so a secret cannot leak through this path. Nothing secret goes into a mobile environment at all — the mobile app reaches only public `/healthz` against no session.
- **Product-facing text (the healthcheck screen's strings) is Bahasa Indonesia.** Everything written for developers — this plan, code comments, commit messages, config — is English.
- **`ios/` and `android/` are prebuild outputs and stay gitignored.** They are generated by `expo run:*`, not hand-maintained; committing them invites the manual native drift Expo exists to avoid.
- **One `.env` at the repository root belongs to the backend and mobile must not read it.** `apps/mobile` gets its own `apps/mobile/.env.<variant>` files. This is the repo's standing security boundary made concrete.

```
   runner (Bun's equivalent of npm --workspace). Never introduce a nested
   lockfile inside apps/mobile.

3. The root package.json workspaces are ["apps/*","packages/*"], so apps/mobile
   is auto-included the moment it has a package.json — no root package.json edit
   is needed for membership.

4. The Makefile does `-include .env` then `export`, handing the ROOT backend
   .env (DATABASE_URL, REDIS_URL) to EVERY recipe, mb-* included. This does NOT
   breach the mobile boundary: only EXPO_PUBLIC_-prefixed vars are ever inlined
   into the bundle, and a backend secret has no such name. mb-* targets consume
   neither DATABASE_URL nor REDIS_URL; they run bun/expo inside apps/mobile.

5. The root .gitignore ALREADY ignores `.env` and `.env.*` (with only
   `!.env.example` re-included), AND already has an Expo/RN section (`.expo/`,
   `*.jks`, `*.p8`, `*.p12`, `*.keystore`, `*.mobileprovision`). Consequences:
   (a) a committed apps/mobile/.env.development needs an explicit `!.env.development`
       re-include in apps/mobile/.gitignore — the parent DIRECTORY is not ignored,
       only files matching `.env.*`, so a child negation re-includes it;
   (b) apps/mobile/.gitignore's real job is that re-include PLUS ignoring the
       native output `/ios/` and `/android/` — node_modules/.expo are already
       covered by root. This is the OPPOSITE of what the spec sketch implies and
       is the reconciliation to record.

6. The Makefile `dev` target already carries a TODO comment (around lines
   120-121) naming the exact mobile line to add to its process group:
     ( bun run --filter @anakmobil/mobile start 2>&1 | awk '{print "[mobile]  " $$0; fflush()}' ) &
   Follow that comment; do not invent a different shape.

7. Typed routes are generated WITHOUT a dev server by `expo customize
   tsconfig.json` (writes .expo/types/router.d.ts and reconciles tsconfig).
   `.expo/` is gitignored, so CI regenerates it. This command must run BEFORE
   `tsc --noEmit`, locally and in CI, or tsc checks stale/missing route types.

8. Node LTS must be on PATH for `expo prebuild` (it shells to `npm pack`). Bun
   runs installs, scripts, and Metro; prebuild is the one Node touchpoint.

9. The default template is app.json + a tabs example under app/. This ticket
   converts to app.config.ts (dynamic) and prunes to app/_layout.tsx +
   app/index.tsx only. Delete app.json when app.config.ts lands; two configs
   with conflicting keys is a merge surprise.

10. Do NOT set `"type": "module"` in apps/mobile/package.json even though
    apps/landing does. Expo's toolchain (Metro, babel, app.config loading)
    assumes CommonJS interop; forcing ESM breaks config loading. This is a
    deliberate divergence from the landing analog.

11. Owner-only steps cannot be run from this environment: `eas init`, `eas
    login`, `eas env:set/pull`, `expo run:ios`/`expo run:android` on a device,

    owner's Mac, Xcode/Android Studio, an Apple signing identity for a physical
    iPhone, and a connected phone. The plan marks each such step OWNER.

12. Gate chain for a mobile code change, from the repository root, checking
    EXIT CODES (piped output is not evidence):
      bun install --frozen-lockfile          # bun.lock must be unchanged
      make mb-check                           # type-gen -> tsc --noEmit -> expo lint
```

## JS/TS quality gate — Block Q (NOT Sonar)

**Paste verbatim into every brief that writes TypeScript.** This repository runs **no SonarQube** for JS/TS. Telling an implementer to invoke Sonar sends them after a tool that is not installed. The gate is `mb-check` plus the standing rules below.

```
# Mobile JS/TS quality gate — write compliant from the first commit (NO Sonar)

- `make mb-check` is the gate, three steps in this fixed order:
    1. bun run --filter @anakmobil/mobile check  ->  which runs, in order:
       a. expo customize tsconfig.json   (generate .expo/types/router.d.ts)
       b. tsc --noEmit                    (strict type-check)
       c. expo lint                       (ESLint, Expo flat config)
  Step (a) MUST precede (b); tsc against stale route types checks the wrong thing.
- tsconfig extends expo/tsconfig.base (which is already `strict: true`); the
  explicit `"strict": true` we add is belt-and-suspenders and cannot be weakened
  by `expo customize` regenerating tsconfig, because the base stays strict.
- NO explicit `any`. Enforced by an ESLint rule
  `@typescript-eslint/no-explicit-any: error` added to eslint.config.js, on top
  of strictness. Prefer `unknown` + narrowing (the healthcheck catch does this).
- React component props: prefer `readonly` where a props type is introduced
  (none in this ticket beyond framework-provided).
- `bun install --frozen-lockfile` MUST leave bun.lock unchanged — no nested
  lockfile drift. This is part of the gate, not a nicety.
- Both tsc and ESLint report file:line on failure natively (AC2's requirement);
  no custom reporter is needed, only that `check` chains them and propagates the
  first non-zero exit.

When fixing one instance, scan sibling files for the same shape and fix forward.
When reviewing, check the diff against this list BEFORE marking compliant.
```

## Run-shape verdict (§28)

**Serial, and honestly so — this is a dependency chain, not a queue that could fan out.** Nearly every task edits or reads one of a small set of shared files, and the later ones consume what the earlier ones produce:

- `apps/mobile/package.json` + the root `bun.lock` — touched by Tasks 1, 2 (dotenv dep), 6 (scripts referenced), and the whole gate. A second writer against `package.json`/`bun.lock` reruns `bun install` and races the lockfile.
- `apps/mobile/app.config.ts` — produced by Task 2, has its `extra.eas.projectId` written by Task 5's `eas init`, read by Tasks 3 (typedRoutes), 4 (extra.appVariant), 8 (prebuild).
- `apps/mobile/app/` + the typed-routes gate — Task 3 establishes the gate mechanics, Task 4 fills the screen and must keep it green.
- `Makefile` — Task 6 adds `mb-check`, the `mb-run-*` targets, the `check` aggregate line, and the `dev` line; `mobile.yml` (Task 7) deliberately mirrors `mb-check`, so CI cannot be written before the target it mirrors exists.

No two tasks touch disjoint files with no produces→consumes edge, so there is nothing to run concurrently. Combined with the heavy owner-device dependency at the tail (Tasks 5, 8, 9), a single-writer serial run is the correct and cheapest shape. Tasks 1–4, 6, 7 are agent-executable and run headless; Tasks 5, 8, 9 are owner-gated at their device/EAS steps and marked so.

**TDD across the ticket:** every task is `TDD: no — verify by running`. There is no domain logic and no input→output contract to pin with a red-first test; the "test" is running the command and reading the result (`mb-check` reddens on a seeded error and names the file:line; the screen renders the right URL and `/healthz` result on device). Each task states its verdict explicitly anyway.

## Tidak boleh ada

The spec's anti-goals, carried here so a task cannot quietly grow past its brief. Anything on this list appearing in a diff is a finding, not an improvement.

- **No design system, no theme wiring, no fonts.** `packages/tokens` is not consumed. The healthcheck screen is deliberately plain — a title, two lines, a status. A couple of inline status colors is not a design system and is permitted; a token import, a font load, or a theme provider is not.
- **No navigation structure beyond the one required `_layout.tsx`.** Expo Router is installed and its single root `_layout.tsx` (a bare `Stack`) exists; there are no tabs, no nested stacks, no routes beyond `app/index.tsx`. Navigation is its own later story. The template's tabs/example screens are deleted, not kept "for later".
- **No API client.** The screen calls `/healthz` with a bare `fetch`. No client abstraction, no auth, no interceptors, no generated types wired in.
- **No EAS cloud build in the AC1 path.** `eas.json` is configured and `eas init` runs so cloud builds are one command away, but AC1 is proven by a local `expo run:*`. Cloud builds are available, not required.
- **No app-store submission, no signing config beyond what a local dev build needs, no push notifications, no OTA/update channel.**
- **No authentication.** The app reaches only public `/healthz`.
- **No hand-rolled `metro.config.js` monorepo tuning.** Current Expo SDKs auto-detect the Bun workspace; a hand-written `watchFolders`/`nodeModulesPaths` is obsolete maintenance surface. Use `expo/metro-config` untouched (or the template's default) — do not add workspace plumbing to it.
- **No `"type": "module"` in `apps/mobile/package.json`** (Block M item 10), despite the landing analog using it.

- [ ] **Step 2: write `app.config.ts`**

```ts
import { config as loadEnv } from 'dotenv';
import type { ExpoConfig } from 'expo/config';

// APP_VARIANT is a non-prefixed build-time var (NOT inlined into the bundle).
// It selects the app identity and which env file supplies the one public value
// the bundle does carry. A local `expo run:*` defaults to development, so the
// Makefile mb-run-<variant> targets set this explicitly — otherwise only the
// development profile is ever really proven (spec [grill]).
type Variant = 'development' | 'preview' | 'production';
const VARIANT = (process.env.APP_VARIANT as Variant) ?? 'development';

// Load the matching env file so `expo config` and EAS resolution see
// EXPO_PUBLIC_API_URL even outside the Makefile. The Makefile also sources the
// file into the process env (the primary path babel inlines from); this load
// is the belt-and-suspenders for bare `expo config`.
loadEnv({ path: `.env.${VARIANT}` });

const APP_ID: Record<Variant, string> = {
  development: 'id.anakmobil.app.dev',
  preview: 'id.anakmobil.app.preview',
  production: 'id.anakmobil.app',
};

const APP_NAME: Record<Variant, string> = {
  development: 'AnakMobil (Dev)',
  preview: 'AnakMobil (Preview)',
  production: 'AnakMobil',
};

const config: ExpoConfig = {
  name: APP_NAME[VARIANT],
  slug: 'anakmobil',
  scheme: 'anakmobil',
  version: '0.1.0',
  orientation: 'portrait',
  newArchEnabled: true,
  ios: {
    bundleIdentifier: APP_ID[VARIANT],
    supportsTablet: true,
  },
  android: {
    package: APP_ID[VARIANT],
  },
  plugins: ['expo-router'],
  experiments: { typedRoutes: true },
  extra: {
    appVariant: VARIANT,
    // Written by `eas init` in Task 5. Until then no EAS command resolves,
    // which is fine — AC1 needs no EAS.
    eas: { projectId: 'REPLACE_AFTER_EAS_INIT' },
  },
};

export default config;
```

Keep the template's icon/splash asset references if the scaffold placed them under `ios`/`android`/top-level; carry them across from the deleted `app.json` verbatim rather than dropping them (a missing icon fails prebuild). If the template used top-level `icon`/`splash`, add those keys back here unchanged.

```tsx
          {status === 'terhubung'

        </Text>
```
